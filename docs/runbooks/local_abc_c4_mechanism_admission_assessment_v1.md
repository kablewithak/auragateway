# Runbook: C4 Mechanism-Admission Assessment V1

## Purpose

Generate and verify the static Qualification Contract V2 and C4 mechanism
admission assessment from current repository authorities.

This runbook performs no model, GPU, Kaggle, network, or authorization action.

## Preconditions

- repository branch is the intended qualification-reconciliation feature branch;
- the four preserved C4 paragraph-order lifecycle originals remain untouched;
- Python virtual environment is active;
- current repository authorities are present at their exact expected hashes.

## Generate

```powershell
python -m auragateway.local_abc.c4_mechanism_admission_assessment_v1 `
    --repo-root . `
    --write
```

Expected summary includes:

```text
semantic_c4_state=NOT_QUALIFIED
p5_requalified=false
p6_requalified=false
model_requests_performed=0
gpu_execution_performed=false
kaggle_execution_performed=false
new_execution_authorized=false
```

The exact `mechanism_admission_state` is derived from repository evidence.

## Verify deterministic regeneration

```powershell
python -m auragateway.local_abc.c4_mechanism_admission_assessment_v1 `
    --repo-root . `
    --check
```

## Focused tests

```powershell
python -m pytest `
    tests/unit/local_abc/test_c4_mechanism_admission_assessment_v1.py `
    -q
```

## Static validation

Run the repository's existing Ruff/mypy validation pattern for the explicit
changed Python files, followed by:

```powershell
git diff --check
```

## Stop conditions

Stop and report the exact error if:

- an authority SHA differs;
- the C4 review no longer binds the expected disposition record;
- the P5/P6 design allows model semantics as route proof;
- generated bytes drift;
- focused tests fail.

Do not repair historical evidence to make the assessment pass.

## Authority boundary

A successful static assessment does not authorize P5/P6 execution.

A future live runtime requires a separate design, implementation,
repository acceptance, and single-use execution authorization.
