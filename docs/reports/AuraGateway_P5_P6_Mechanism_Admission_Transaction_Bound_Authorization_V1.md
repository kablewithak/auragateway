# AuraGateway P5/P6 Mechanism-Admission Transaction-Bound Authorization V1

## Result

This implementation restores the P5/P6 Mechanism-Admission Successor to the
repository's accepted transaction-bound execution-authorization architecture.
It does not issue live authority and does not execute the runtime.

The implementation uses two separate authority lines:

- behavioral/runtime authority: the merged P5/P6 Mechanism-Admission Successor
  implementation from PR #290;
- authorization/control-plane authority: the transaction-bound architecture
  restored by the PR #292 reconciliation.

PR #291 remains preserved as historical implementation evidence with the
reconciliation disposition `IMPLEMENTED_BUT_SUPERSEDED_BEFORE_LIVE_ISSUANCE`.
Its authorization-control producer/input topology is not reused.

## Runtime integration

A producer derives a new versioned runtime payload from the merged PR #290
runtime template. The transform is deliberately narrow:

1. materialize the frozen PR #290 runtime placeholders;
2. remove the authorization-control discovery/materialization block;
3. insert `require_transaction_bound_context()`;
4. replace the single runtime authorization-consumer call with the
   transaction-bound context call;
5. fail if stale control-input tokens remain;
6. compare the ASTs of `observe_structured_response`,
   `run_structured_request`, `decide_p5`, and `decide_p6` before and after the
   transform.

The runtime therefore remains behaviorally owned by PR #290 while authorization
admission is owned by the outer transaction-bound wrapper, matching the earlier
P5/P6 transaction-bound integration precedent.

## Preserved mechanism contract

The implementation does not reopen the mechanism-admission decision:

- semantic states remain `EXACT_MATCH`, `VALID_JSON_MISMATCH`,
  `NON_OBJECT_JSON`, and `INVALID_JSON`;
- semantic mismatch does not block otherwise valid mechanism evidence;
- invalid JSON alone does not block otherwise valid mechanism evidence;
- `finish_reason == "stop"` remains required;
- response content is represented by digest/provenance rather than raw output;
- raw output logging remains prohibited;
- P5 and P6 do not use semantic state as their mechanism proof;
- P5 and P6 acceptance thresholds are not relaxed;
- the execution ceiling remains 6 model requests, 3 worker starts, 3 model
  loads, and 0 hidden retries.

## Restored authorization lifecycle

After this implementation is merged, a future explicit live-authorization gate
may perform the following lifecycle:

1. require synchronized clean `main` while preserving only the four known
   immutable historical C4 lifecycle files as untracked evidence;
2. construct a fresh authorization intent;
3. require exact manual retype of a dynamic SHA-256 challenge within 15
   minutes;
4. derive the transaction ID from the canonical authorization body;
5. generate one deterministic notebook embedding both authorization and the
   exact versioned runtime payload;
6. persist a fresh durable T4 x2 / Internet Off platform observation after
   artifact generation and before Save & Run All;
7. allow at most one Save & Run All under that transaction;
8. terminalize the authorization after an attempted or unused disposition.

The generated notebook accepts only the durable runtime/wheelhouse and model
snapshot input roles. Authorization-specific Kaggle inputs, authorization
producer notebooks, manual confirmation JSON, runtime authorization filename
discovery, and a platform-observation receipt mounted as runtime input are all
prohibited.

## Generated static artifacts

- review JSON in `benchmarks/local_abc/` with the transaction-bound authorization V1 name;

repository authorities. Generated bytes are validated deterministically before
staging.

## Non-claims

This implementation does not establish:

- live human authorization;
- a Kaggle platform observation for this transaction;
- Kaggle execution;
- model loading or model requests;
- C4 semantic qualification;
- P5 requalification;
- P6 requalification;
- variance adequacy;
- final measured A/B/C effects;
- quality non-inferiority;
- production readiness.
