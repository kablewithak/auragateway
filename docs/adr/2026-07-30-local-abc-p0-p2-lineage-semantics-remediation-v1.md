# ADR: P0-P2 Lineage Semantics Remediation V1

## Status

Accepted for bounded repository implementation. Kaggle materialization remains blocked
until this remediation is merged and the regenerated lineage is inspected.

## Context

The corrected P0-P2 source bundle contains artifact bytes introduced through PR #160,
but the materialization chain labels those bytes with `source_repository_commit` equal
to `831b4ad4e8eb4139b51af927eb721989be197cbc`. That commit predates the corrected P1 source and therefore
cannot be the containing commit for the governed bytes.

The chain also uses `diagnostic_source_main_merge_commit` for
`f4f08eda4b4d4747514b4646fe53664d8a78ca6d`, which is the Option C decision merge rather than the
merge that contains the current diagnostic bytes. The execution launcher similarly uses
`source_main_merge_commit` as a mutable current-lineage identity.

## Decision

Separate immutable artifact identity from repository ancestry:

1. Rename `source_repository_commit` to `source_main_base_commit`.
2. Bind it to `24914d79ef4b4d33285f111c8920d16c36244614`, the clean merged-main commit from which this remediation
   branch was created.
3. Rename `diagnostic_source_main_merge_commit` to
   `option_c_decision_merge_commit` while retaining
   `f4f08eda4b4d4747514b4646fe53664d8a78ca6d`.
4. Rename historical `branch_name` fields to `architecture_origin_branch` and preserve
   `fix/local-abc-cu129-p1-probe-taxonomy-v1`.
5. Regenerate the source bundle, materializer notebook, inspection notebook, execution
   launcher, and their records from producer-owned code.
6. Continue to use SHA-256 as the authority for exact artifact bytes.

## Why a base commit

A generated artifact cannot truthfully embed the future commit that will contain itself.
A clean base commit is stable, non-self-referential, and independently verifiable through
Git ancestry. Exact generated bytes remain proven by their hashes.

## Consequences

The source-bundle and generated-notebook identities change. The diagnostic notebook,
diagnostic request, and implementation-record bytes do not change. Historical Kaggle
versions remain preserved and non-reusable.

## Safety

No Kaggle run, GPU execution, package installation, model load, worker start, model
request, benchmark trajectory, credential use, customer-data use, or external spend is
performed by this repository remediation.

## Non-claims

This ADR does not prove CUDA linking, `cuInit(0)`, Triton compatibility, worker readiness,
cache qualification, measured A/B/C effects, deployment, or production readiness.
